# 소개 페이지 — 「직녀의 베틀」 설계

## 왜 다시 만드나
2026-11-23 화첩 버전(청록산수 장별 구성)을 본 사용자 평가:
- 퀄리티가 떨어져 보인다 — 작은 글씨·얇은 UI가 화려한 그림과 안 어울림, 그림이 흐릿함(화면 캡처로 옮겨서), 그림마다 화풍·배경색이 다름
- 화면 전환이 끊겨 보인다 — 장마다 배경색이 바뀌고 그림이 각자의 틀에 갇혀 있음
- 스토리가 안 보인다 — 장 제목이 추상적, 개념 설명이 많고 결과물이 안 나옴
- 사주 분석·수배전단 페이지와 딴 세상 — 밈 톤(이모지·스티커)

## 목표
- 첫 화면부터 끝까지 **옛이야기 한 편**을 듣는 느낌. 말투는 설화 낭독체("옛날, 은하수 동쪽에는…").
- 외국인도 아는 설화 **견우와 직녀**에, 소울코드의 각색 **"직녀가 사람마다의 무늬(사주)를 짠다"**를 잇는다. 무늬 = 여덟 글자 = 코드(Soul + Code).
- 장면이 **끊기지 않고** 한 그림 속에서 이어진다.
- 컴퓨터에서는 **컴퓨터 화면에 맞춘 가로 구성**. 폰 화면을 키운 모양이 아님.

## 하지 않을 것 (non-goals)
- 밈 톤: 이모지, 스티커, "반박 시 당신 말이 맞습니다" 같은 농담. 이번 페이지에서 전부 뺀다.
- 개념 강의(십신 10줄, 음양·오행·절기 설명 3단). 이야기 안에 한두 마디로만 녹인다.
- 사주 분석(/app)과 수배전단 화면 개편 — 다음 작업(2, 3번)으로 따로 한다.

## 실패로 보는 것 (anti-goals)
- 그림과 글이 따로 노는 '전시장' 느낌으로 돌아가는 것
- 설화 각색을 사실처럼 보이게 하는 것 → "소울코드가 이어 쓴 이야기"라고 밝힌다
- 컴퓨터에서 가운데 좁은 기둥 하나만 보이는 것

## 보여주는 방식 (Approaches)
| | 방식 | 장단점 |
|---|---|---|
| **A — 채택** | 긴 두루마리 한 장 속을 걷기: 그림 무대를 화면에 고정하고, 스크롤하면 장면이 이어서 바뀌며(겹쳐 녹아듦 + 천천히 카메라 이동) 글이 그 위로 한 문단씩 떠오른다 | 끊김 문제를 정면으로 해결. 장면 그림을 같은 구도·색으로 새로 그려야 함 |
| B | 그림책처럼 한 장씩 넘기기 | 설화 느낌 강함, 장마다 멈칫해 흐름이 끊김 |
| C | 영상 오프닝 + 일반 페이지 | 가장 웅장하지만 건너뛰기 쉽고 폰에서 무거움 |

사용자가 A를 따로 고르지 않아 추천안 A로 진행(사용자가 바꿀 수 있음).

## 이야기 (확정 줄거리)
| 장면 | 글 (요지) | 그림 |
|---|---|---|
| 序 | 구름이 걷히며 제목 "SoulCode — 직녀의 베틀" | 금테 구름 (기존 입장 구름 재사용) |
| 一 은하수 양쪽 | 은하수 동쪽 베 짜는 직녀, 서쪽 소 치는 견우 | 밤하늘 은하수, 양쪽 끝 작은 두 인물 |
| 二 갈라진 두 별 | 사랑에 일을 잊어 하늘 임금이 갈라놓음, 일 년에 하루 칠월 칠석 | 같은 은하수, 강물이 넓어지고 두 별이 멀어짐 |
| 三 직녀의 베틀 *(각색)* | 홀로 남은 직녀가 땅에서 태어나는 아이마다 해·달·날·시로 무늬를 짜 줌. 네 기둥, 여덟 올 = 사주 | 베틀 앞 직녀, 비단에 금실 무늬, 아래로 흘러내린 비단이 땅의 마을로 |
| 四 오작교 | 칠석 밤 까치·까마귀가 다리를 놓음. 두 무늬가 맞닿는 자리 = 궁합 | 까치 떼가 이은 다리 위 두 사람 |
| 五 무늬를 읽는 사람들 | 무늬를 읽는 이가 드물어짐 → 소울코드가 한국천문연구원 만세력으로 날짜를 맞추고 오늘의 말로 옮김. **실제 결과 예시(여덟 글자 표 + 한 줄 풀이)** 를 비단 두루마리 위에 보여 줌 | 펼쳐진 비단 두루마리 (결과 예시가 올라가는 바탕) |
| 六 당신의 무늬 | 태어난 날과 시를 알려 주세요 → [내 무늬 읽기] [오작교 궁합 보기] [용모파기 그리기] | 새벽 은하수가 희미해지며 해가 뜨는 하늘 |

끝에 작은 글씨: "견우와 직녀, 칠석, 오작교는 전해 내려오는 이야기이고, 직녀의 베틀 대목은 소울코드가 이어 쓴 이야기입니다."

## 화면 구성
- **무대**: 화면 전체에 고정된 그림 층. 장면이 바뀔 때 앞 그림이 녹아 사라지고 다음 그림이 겹쳐 나타나며, 각 장면 안에서는 천천히 확대·이동(카메라 느낌). 배경색 전환 없음 — 무대 하나가 계속 이어짐.
- **글 층**: 장면마다 한 문단. 컴퓨터는 화면 왼쪽(또는 그림 여백 쪽) 단에, 폰은 하단에 반투명 한지 띠 위에.
- **장면 길이**: 장면당 화면 높이 약 1.5배 스크롤. 진행 표시: 화면 가장자리에 작은 장 번호(一~六) 세로 목록, 현재 장 강조, 클릭하면 그 장면으로 이동.
- **입장**: 구름이 걷히는 연출은 유지(사용자가 좋아함). 命 도장 대신 織(짤 직) 도장.
- **모션은 하나의 흐름으로**: 장면 전환(녹아듦+카메라)과 글 떠오름 두 가지만. 금가루는 은하수 장면에서 별빛으로만. 회전·3D 카드·두루마리 축 등 개별 효과는 뺀다.

## 글씨 (퀄리티)
- 컴퓨터: 이야기 본문 18–20px, 장 제목 40–56px, 버튼 16px 이상, 높이 52px 이상
- 폰: 본문 16–17px, 제목 28–34px
- 아주 작은 영문 고정폭 라벨은 쓰지 않는다. 장 번호는 한자(一~六)와 한글 제목만.
- 글은 그림 위에서도 읽히게: 한지 색 반투명 띠 또는 그림의 비어 있는 하늘 쪽에 배치.

## 그림 (퀄리티)
- 장면 그림 6장을 **한 번에 같은 지시(같은 화풍·색·구도 규칙)**로 생성: 남색 밤하늘·청록·금박선·주홍 포인트, 한지 질감.
- 컴퓨터용 가로(16:9)와 폰용 세로 구도가 둘 다 살도록, 주인공은 가운데 세로 띠에 두고 양옆은 하늘·구름으로 여유.
- **원본 해상도 그대로 옮긴다**: 화면 캡처 대신 원본 PNG를 받아서 WebP로 변환. (방법: 내장 브라우저로 사용자 컴퓨터에 내려받은 뒤 작업 공간으로 가져오기 — 다운로드할 때 사용자 허락 필요)

## 기술
- 기존 구조 유지: `components/Landing.tsx`(정적 마크업+스크립트), `app/landing.css`(.sc5 범위), 그림 `public/landing/story/`.
- 고정 무대는 CSS `position:sticky` 또는 fixed + 스크롤 진행률로 투명도·확대 계산(requestAnimationFrame).
- 모션 줄이기 설정 시: 장면은 정지 그림이 차례로 나오고 글은 바로 보임.
- 링크: 내 무늬 읽기 → /app, 오작교 궁합 → /app 궁합 탭, 용모파기 → /wanted(3번 작업 전까지는 기존 화면).

## 건설자에게 맡기는 것
- 각 장면 그림의 세부 구도, 녹아듦 곡선과 속도, 진행 표시의 모양
- 문장 다듬기(위 요지를 설화 낭독체로)
